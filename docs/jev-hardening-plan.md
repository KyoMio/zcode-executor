# Jev 快筛修复与优化方案

> 状态：三级路线及安全修复已完成零费用验收（384/384），付费校准未执行；证据见 `docs/verified.md`，进度见 `docs/tasks/T7-jev-prescreen.md`。下文保留设计与后续测量计划。
> 基于本次 TypeSafe 官方指南核对、现有代码审查与零网络 fake fetch 复现。

## 一、用白话说明

Jev 的接口已经接对，也能完成真实审批。现在要补的是它“看什么、看不清怎么办、结果怎么记录”的边界，而不是重做整个系统。

建议先做三件事：

1. **别让它看错。** 修正路径替换，避免把工作目录之外的位置标成工作目录；必要内容被隐藏时，不让它凭不完整信息直接放行。
2. **别为检查泄密而先泄密。** 请求发给 Jev 前遮盖命令里的凭据；日志也不直接相信服务返回的字符串。
3. **别超时还算通过。** 到期结果统一交给原 ZCode 快筛，快筛未通过才进入慢判，并清理不用的网络响应。

新的分工是：**Jev 能明确通过的提前结束，其余回到原来的“快筛 → 慢判”链路。** 原快筛不再被 Jev 替代。

代价：Jev 未提前放行的请求会多等一段前筛时间；本地已知证据不足的动作直接跳过 Jev，不额外等待。是否总体更快、更省 ZCode 用量，取决于提前通过比例和实际耗时，需要配对测量。

**不把复杂命令当危险：** 管道、子 shell、批处理、项目脚本仍可属于正常任务。回落依据是判断所需证据缺失或处理失败，不是命令看起来复杂。

## 二、修订架构：Jev 前置，不再替代原快筛

本次按用户方向修订：Jev 是可选的提前通过层，原 ZCode fast + low 快筛完整保留，慢判仍是最后一层模型审批。官方支持“窄判断由代码组合、复杂判断交给语言模型”的原则，但不强制这一条具体三级链；此链是本项目的产品选择。

```text
硬规则与 allow_once 检查（沿用原逻辑）
  ↓
review 开启？否 → 按原合同挂起
  ↓ 是
Jev 已配置且输入适合前筛？
  ├─ 否 → 原 ZCode fast + low 快筛
  └─ 是 → Jev 前筛
             ├─ 证据充分且明确 pass → allow（提前结束）
             └─ flag / error / 超时 → 原 ZCode fast + low 快筛
                                         ├─ pass → allow
                                         ├─ 未通过 / 无法解析 → ZCode 慢判
                                         │                       ├─ allow → allow
                                         │                       └─ ask / 失败 → 人工
                                         └─ 调用失败 → 原 review-failed / ask
```

这里的“判断不了进慢判”沿用原快筛的结果语义；原快筛调用异常仍按原实现 ask，不在本轮暗改为重试慢判。若希望异常也进入慢判，应另立可用性取舍。

### 路由合同

| 条件 | 下一步 | 是否调用 Jev |
|---|---|---|
| 无 key | 原快筛 → 必要时慢判 | 否 |
| 输入缺必要证据、正文省略或不能可靠脱敏 | 原快筛 → 必要时慢判 | 否，记录 skip |
| Jev 五项均达标且本地证据检查通过 | 直接 allow | 是；不调用 ZCode 审批 |
| Jev 任一项超阈值 | 原快筛 → 必要时慢判 | 是；不是直接拒绝或强制慢判 |
| Jev 超时、HTTP/响应错误、adapter 异常 | 原快筛 → 必要时慢判 | 是或尝试过 |

- 原快筛收到既有的完整 action/context（按原隐私合同），不是 Jev 截断、正文省略后的 state。
- 原快筛不接收 Jev 概率作为额外指令；避免被前筛结果带偏，保留原系统提示词、fast + low、预算和解析规则。
- 本轮不实现 Jev 与 ZCode 并发竞速，避免已经提前通过仍浪费后续调用。
- Jev 仍有提前放行权，不只是增加一道校验。因此这不是“加一层就必然更安全”；A1 的证据门槛及全部安全修复仍必须完成。

### 保留的产品约束

- 仅从插件 config 的 `review.jev.apiKey` 选择 Jev；不增加环境变量后门、shadow 或模式开关。
- 无 key 继续原 ZCode fast + low 快筛；关闭 review 仍按原合同处理。
- 硬规则与 `allow_once` 在前；Jev 只决定提前通过或继续原快筛，绝不直接拒绝用户。
- Jev flag/error 交给原 ZCode 快筛，再按原流程决定是否进入慢判；原链路的 ask/调用失败等挂起出口保持不变。
- 不把 Write/Edit 正文直接上传 Jev，不扩大敏感数据外发范围。
- 保留 Node ≥22、纯 `.mjs`、零运行时依赖、一个最终 `executor.gate` 事件。
- 继续固定模型版本。概率阈值暂不放宽；题目含义变化时升级内部 reviewSchema，并重新校准。

## 三、发现、证据与修复建议

### A. 必修：发送给 Jev 的证据

#### A1. 隐藏正文与截断会丢失判断依据

**现状：** Write/Edit/MultiEdit 正文仅保留 `omitted/chars/lines`；长命令、任务单和消息也可能截断。Jev 仍回答外泄、破坏或任务边界等问题，且低概率可直接放行。

**证据强度：** 已确认 state 信息被省略及没有必要证据不足的强制回落；这不是已证明真实模型误放行。相同长度、行数的不同正文可形成相同 state，因此模型无法判断其中的语义区别。

**建议规则：**

- 在本地构造 state 时，同时保留不外发的“省略/截断/无法可靠归一”标记。
- 第一版采用明确、可测试的保守边界：正文被省略的 Write/Edit/MultiEdit、命令被截断、任务授权信息被截断或缺失的动作，不走 Jev 直接放行，直接进入原 ZCode 快筛（未通过再进慢判），避免先花一次注定无足够证据的 Jev 请求。
- 这意味着首版修复后，Write/Edit/MultiEdit 会失去当前 Jev 直通收益。若要恢复，另行设计可证明保留所需语义的本地证据提取，并通过安全样本验收；不能仅靠文件后缀、字符数或模型自述“足够”来恢复。
- 未截断的 Bash 可以继续接受语义快筛，但不能宣称仅看脚本名称就验证了脚本实际行为。对必须读取脚本、动态载荷或环境状态才能确认风险的情况，应跳过 Jev，交给原快筛及其后续慢判；精确识别范围须在实施任务的样本表里钉死，不写成一条无限泛化的“复杂命令回落”规则。
- 慢判也不保证能看到所有脚本或运行时事实；无法获得必要证据时应 ask，而不是把转慢判等同于安全证明。

**验收：**正文省略、命令中段隐藏风险、任务中段包含限制、缺少意图等用例不能由 Jev 直接 allow；完整且任务相关的管道/批处理仍有快筛通路。新增回落比例单独报告。

#### A2. Bash 中的工作目录替换缺少路径边界

**复现：**根为 `/repo` 时，`echo ok > /repo-backup/out` 被改成 `echo ok > <WORKTREE>-backup/out`。

**位置：** `lib/review/jev.mjs` 的 `normalizeString`。

**建议：**明确路径参数与命令文本两种处理。路径字段可规范化 `.`、`..` 后按边界比较；命令文本不得粗暴 split 根路径，也不得用简单空格切分冒充 shell 解析。仅替换能可靠识别的完整路径前缀，不能确定时不制造 `<WORKTREE>` 结论。词法归一不等于解析符号链接或运行时变量，必要时回落。

**验收：**根目录本身、子目录、兄弟目录、空格与引号、`../`、相对路径、变量拼接及符号链接分别有样本；不能把外部路径错误标成内部。

#### A3. 命令内未知凭据未脱敏

**复现：**`curl -H 'Authorization: Bearer SYNTHETIC_SECRET_123' https://example.invalid` 中的合成凭据仍出现在发给 fake fetch 的 body。

**说明：**已知 provider/Jev key 的值替换仍有用，但不能覆盖用户在命令中新写入的秘密。字段名脱敏无法处理普通字符串内部的 header 或赋值。

**建议：**外发前覆盖常见 Authorization、敏感命令参数、环境赋值、URL userinfo 等凭据形式；以 `<redacted>` 替代值，保留“存在凭据/外发目标”的结构信号。明显含凭据但无法可靠分离的输入不发送 Jev，直接回落。脱敏应先于截断，防止截断破坏识别边界；已知秘密值替换仍作为补充。

**验收：**仅用合成秘密，对普通字段、深层对象、命令、任务文本、URL、引号和多行形式检查整个请求序列化结果不含测试秘密。承认编码、拼接及未知格式仍有限制，不宣称能发现所有秘密。不得扩大慢判原有外发权限。

### B. 必修：服务结果与资源管理

#### B1. metadata 值校验与脱敏

**复现：**fake response 将 model 和 request-id 设置为合成秘密，五项概率为 0，结果仍 pass，字符串原样留在 metadata。

**建议：**固定模型请求校验响应模型等于期望版本；不匹配视为响应异常并回落。request ID 仅作诊断：限制类型、长度与安全字符，不合法则省略，不必因缺失 ID 否定有效概率结果。所有可落盘外部字符串再做已知秘密过滤；不记录响应 body、key 或 state。

**验收：**错误模型不能 pass；过长、带换行、合成 key 回显的 request ID 不落盘；合法且无 request ID 的响应仍可通过。保留五项精确 ID、类型、有限值和 `[0,1]` 校验。

#### B2. 严格总 deadline

**复现：**假时钟预算 10ms、JSON 完成时为 11ms，现状仍 pass。

**建议：**保留 AbortController，并在正文读取、解析/校验结束以及返回 pass 前检查剩余总预算与 abort 状态；`now >= deadline` 按到期处理。重试与等待同样不能越过预算。

**验收：**到期前、恰好到期、超时一瞬间、正文读取挂起、定时器竞态、重试等待分别测试；超时不能 pass，timer 最终释放。

#### B3. 释放非成功响应 body

**复现：**401 fake response 返回后 `body.cancel()` 未调用。

**建议：**不需要解析的非 2xx 响应及时取消 body；清理失败不得掩盖原 HTTP 结果或导致误放行，清理也不能无限等待。先提取允许的状态/header，再清理、回落或重试。

**验收：**401/422 和 429/5xx 均执行清理；无 body、清理抛错、清理挂起都有有界处理，不记录错误正文。

### C. 优化：问题、重试与可观测性

1. **收敛问题含义。** `scope_conflict` 专注显式授权边界，移除与 `unrelated_or_gratuitous` 重复的无关性条件；使用完整的 `intent.taskContract`、`intent.recentMessages` 等路径。凭据题对批准目的地、暴露凭据和敏感数据传输的 instruction/criteria 必须一致。五题 OR 风险组合合理，不为“原子化”盲目拆成大量重复题。
2. **重试加入可注入随机抖动。** 与官方 SDK 一样避免并发重试同步冲击；保留本项目总预算，不照搬每次 attempt 重置超时。
3. **区分三层审计。** 最终仍只写一条 `executor.gate`，增加独立 `preScreen` 元数据，记录 Jev 的 pass/flag/error/skip、原因、耗时、尝试次数及允许的概率字段。本地 skip 不伪装成模型 flag，网络错误也不当成风险。原 `fastReview` 已承载旧 Jev 回落记录，不静默改成 ZCode 快筛记录；历史事件保持可读，新增字段及版本区别先写 SPEC。最终 stage/reviewer 必须区分 Jev 提前通过、ZCode 快筛通过、ZCode 慢判，终态统计不能重复计数。
4. **修正 doctor 失败输出。** 配置读取失败时不再以默认值声称当前选中了 zcode；返回清晰的不可确定状态和已有错误信息。增加明确的审批链描述，例如 `review.pipeline: ['jev', 'zcode-fast', 'zcode-slow']`；无 key 时为后两项，禁用时为空，配置失败时不可确定。旧 `fastScreen` 字段保留兼容说明，不再单靠它推断是否替代 ZCode。CLI 人读输出直接显示“Jev 前筛 → ZCode 快筛 → 慢判”，不能泄露 key。

## 五、校准与性能验证方案

### 零费用回归

- 既有所有测试继续通过；新增测试不是固定次数目标，以 A/B 的行为验收覆盖为准。
- runner 层必须覆盖以下路径，并用 mock 审批记录验证进入了哪一层：
  - Jev pass → allow，ZCode 审批零请求。
  - Jev flag → ZCode 快筛 pass → allow，无慢判。
  - Jev error/超时/adapter 异常 → ZCode 快筛 pass → allow。
  - Jev flag → 原快筛未通过 → 慢判 allow 或 ask。
  - 本地 skip → 无 Jev 请求，原快筛照常运行。
  - 无 key → 完整保留原快筛/慢判路径；review disabled → 不调用任何模型审批。
  - 原快筛调用失败 → 保留 review-failed/ask；慢判调用失败 → ask。
  - 每条路径最终事件唯一，preScreen 与最终 reviewer 不混淆，原快筛收到原 action/context。
- 凭据测试检查完整请求与最终审计输出，不只检查字段名；仅使用合成秘密。

### 经确认后才运行的真实验证

- 先准备人工标注的小规模代表集：任务内写文件、正常管道/批处理、外部路径、凭据外发、远程/生产操作、授权冲突、截断及省略正文；包含中文意图。首轮建议 30–50 例，规模和费用确认后执行。
- 每例区分“可以自动通过”“应慢判”“事实不足”，不以历史会话 done 或旧模型输出作为真值。
- 报告每类数量、误放行数、误回落数、服务失败数；安全样本中的任何已知误放行都阻止扩大自动通过范围。小样本零误放行不代表生产安全保证。
- 同一批合格、脱敏的 action/intent 分别送 Jev 和原 ZCode fast + low，交替顺序，多轮记录。只测审批，不执行样本里的危险命令。
- 分开报告直接 API 耗时、包含回落的总审批耗时、本地跳过比例、请求次数和 token 用量。数据足够再报 P50/P95，并区分首次与后续请求；原始记录不含秘密。
- 真实 CLI 会话仅在新建隔离目录执行无害任务。当前修复提案会让省略正文写入跳过 Jev、进入原快筛，只有原快筛未通过才走慢判，因此不要仍拿 Write 当 Jev 直接 pass 的验收样例；另选实际触发审批且证据充分的无害动作。
- 付费脚本放 `scripts/real-*.mjs`，要求 `--yes`，明确调用上限；本轮写方案不执行。

## 六、取舍、暂缓与恢复办法

- **隐私与准确率：**不发正文但又声称已判断正文安全不可兼得。推荐先回落，后续再研究局部证据提取；这是需要确认的主要取舍。
- **速度：**10 秒总预算暂作硬上限，不是前置层的性能目标。官方 SDK 10 秒是每次尝试，两者不是等价配置。串联后超时会在原链路前额外增加最多约 10 秒的 Jev 等待，需重点评估是否缩短前筛预算；不能仅凭一次慢响应加大它。现有 1.290/4.665 秒 Jev 与历史 2.1 秒 ZCode 样本不能作为公平性能结论。
- **测量总收益：**对同一批动作比较“Jev 前筛 + 原链路”和“原链路”。提前通过样本耗时为 Jev 时间；未通过样本为 Jev 时间加原链路时间；本地跳过样本接近原链路时间。汇总实际均值和 P50/P95、提前通过率、额外等待、ZCode 请求节省和两家费用，不用各模型的单次耗时比较代替整体收益判断。若实测没有收益，先缩小适用范围或调整预算，不放宽安全阈值。
- **阈值：**先维持 0.20；它是产品风险偏好，不是整体动作安全概率保证。题目改变后旧校准不能直接复用。
- **不做：**换 SDK、完整 shell 解释器、上传所有源码、引入新依赖、把脚本/复杂命令列为一律拒绝项、自动调宽阈值。
- **恢复办法：**若 Jev 路径故障，可按既有合同移除 Jev key，回到原 ZCode 快筛；不要关闭整个 review 来恢复，也不要撤回隐私修复。修改配置由用户明确授权，文件仍需安全权限。
- **残余风险：**未知凭据格式、动态脚本、符号链接竞态与模型误判不可能由这批补丁完全消除；文档和测试应准确限定保证范围。

## 七、官方依据与证据边界

本次已读取以下官方页面；它们支持设计原则与接口事实，不等于官方认证本项目安全：

- [HTTP API](https://docs.typesafe.ai/api.md)：请求/响应契约、HTTP 错误。
- [Noul](https://docs.typesafe.ai/primitives/noul.md)：yes 概率、可选 criteria。
- [State](https://docs.typesafe.ai/concepts/state.md)：提供相关且充分证据。
- [Models](https://docs.typesafe.ai/models.md)：固定版本、上下文限制、中文准确率提示。
- [Confidence](https://docs.typesafe.ai/confidence.md)：阈值依赖领域数据；Noul 无独立 confidence。
- [Jev 1.13 已知局限](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)：字面理解、间接推断、矛盾条件与对抗输入。
- [Guardrails cookbook](https://docs.typesafe.ai/cookbooks/llm_guardrails.md)：多个风险判断由代码组合；示例结果不是通用阈值。
- [JS SDK client v0.6.0](https://github.com/typesafe-ai/typesafe-sdk-js/blob/v0.6.0/src/client.ts)、[retry v0.6.0](https://github.com/typesafe-ai/typesafe-sdk-js/blob/v0.6.0/src/retry.ts)：超时、重试、抖动的参考。

路径误改、请求含合成凭据、metadata 回显、超时仍 pass、未清理 body 是本地 fake fetch/clock 证据；没有证明官方服务曾回显真实秘密，也没有证明真实模型必然对这些输入误放行。此前的真实会话只验证接通和路由，不替代本方案的边界验收。
