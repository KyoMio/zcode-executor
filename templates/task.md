## 证据块（Proof Manifest，收尾必填）

收尾前在工作区根写 `.executor-proof.json`（不进 git 提交），如实填：

```json
{
  "commands": [{ "cmd": "npm test", "exitCode": 0, "summary": "847 passed, 0 failed" }],
  "artifacts": ["产物/截图/日志的路径，相对于工作区"],
  "unverified": ["诚实列出没验证到的项，比如「未在真机模拟器验证」"],
  "prematureStop": false
}
```

- `exitCode` 必须是真实跑出来的退出码，不许只写「测试通过」四个字；
- 做不完提前收手时 `prematureStop` 写 `true` 并说清停在哪——瞒报比做不完严重得多；
- 写不了文件时，把同一份 JSON 放进最终回复的 ```` ```executor-proof ```` 围栏块里也能算数；
- 没证据的回合会被打回，证据是验收的入场券不是附加分。

## 断点（长任务，派单带 --checkpoint 时适用）

每完成一个子阶段，把进展写进工作区根的 `.executor-checkpoint.md`：
已完成项、已跑通的命令、未完成项、当前阻塞点。回合超时或被取消时，
这份断点决定续跑从哪接，写细一点就是给自己省一遍重跑。

## 排查止损（investigate 类任务）

同一个根因假设连续验证 2 次不成立，立即停止继续打补丁：改写最小复现/证伪脚本，
汇报当前假设与已排除项。单方向死磕到超时是最差结局。
